# 岸桥四轴控制

`smart_port.usda` 已组合 `sts_controls.usda`，场景中 7 台同型岸桥可独立控制。
默认选中中间的 `STS_04`（原 `CODEx_STS_Crane1`），其余可在面板下拉框选择。

## 在已经打开的 Omniverse / Isaac Sim 中使用

打开项目场景，在 Script Editor 执行：

```python
import runpy
runpy.run_path(r"D:\dnt\project\Smart Port RTG Digital Twin\omniverse\scripts\sts_control.py", run_name="__main__")
```

如果软件是在此次修改前打开的，脚本会在会话层挂入新的岸桥层。
不需要丢弃未保存修改或强制重载整个场景。再次执行会释放旧面板并恢复初始姿态。

也可以通过项目根目录的 `start_sts_controls.cmd` 启动新的 Isaac Sim 实例，
或给现有启动命令加 `--enable-sts-controls`。

## 面板操作

| 字段 | 含义 | 范围 |
| --- | --- | --- |
| Gantry offset | 大车相对原停机位置、沿码头世界 Y 轴的位移 | 每台独立限制，不越过相邻岸桥的分区 |
| Seaward reach | 小车海侧方向的局部控制坐标，负数为陆侧 | -10 至 17 场景米 |
| Hoist coordinate | 起升局部控制坐标，经过门架高度缩放后映射到世界高度 | 当前 0.3 至约 16.55；随立柱抬升量调整 |
| Boom up | 海侧前主梁仰角，0 为水平 | 0 至 80 度 |

输入目标后按相应行的 `Go`，轴会按速度限制连续运动；下方 `Actual` 显示当前值。
默认速度：大车 1、小车 0.8、吊具 0.6 场景米/秒，前梁 4 度/秒。
`Focus` 将视图对准所选岸桥。切换岸桥会保持各台的当前姿态并停止尚未结束的移动。

抬梁顺序：

1. 按 `Park for luffing`，等待小车到 -8、吊具到约 16.25（按抬升量自动计算）。
2. 按 `Raise 80 deg`，或输入所需角度后按 `Go`。
3. 按 `Lower 0 deg` 落梁；完全落平后才能把小车重新开到海侧或降低吊具。

前梁角度大于 0 时，小车必须在陆侧 -6 米以外，起升坐标至少约 16.05（按抬升量自动计算，并非世界高度）。
联锁同时检查当前姿态和目标姿态，不能用一次同时下发“停车+抬梁”绕过。
`STOP ALL` 立即停止所有已激活的岸桥；`Resume selected` 解除所选岸桥急停，
之后重新下发目标。关闭面板释放控制并恢复原始停机姿态。
控制使用应用更新时钟，即使时间轴未播放也能操作。

## 模型与范围

前梁原始铰点来自模型海侧梁/中梁接缝（局部坐标 0, 0.94, 9.36），运行时加上 `sts:upperOffset`，随平台抬升及海移。
前梁两侧栏杆、走道、轨道和装饰网格在该平面处分割；后梁、机房和门架固定。
吊具随小车移动，吊绳长度随起升变化；前拉索一端固定在塔顶，另一端随前梁运动。
大车移动只带动岸桥，原有码头轨道和轨枕保持原位。

这是可交互的运动学仿真。距离使用原模型的场景尺度，尚未接入真实 PLC 标定、
载荷动力学、吊具抓箱或船舶/货物碰撞检测；现有简化模型也未做全行程机械干涉校核。
运行时修改写入独立匿名会话层，不保存到 USD 源文件。

## 维护

### 当前轨距：23.31 米（只加宽下部门架）

`sts_track_gauge.usda` 是最上层覆盖：在此前 15.54 米轨距上增加 50%，陆侧立柱、柱脚、轮组及陆侧轨道外移约 7.77 米，海侧保持不动。柱身高度和粗细不变，横梁与斜撑延长并保持两端连接。现有 40 米码头平台足够容纳新轨距，无需再次扩宽地面。

顶部小平台居中：以机房白色顶板中心对齐两侧轮轨/立柱中心线的中点，小平台、机房、塔柱及塔顶锚点整体向陆侧平移约 5.415 米；不移动下方整条主梁、前后臂、吊具、门架或地面。前后拉索的塔顶端随 `sts:towerOffset` 更新，梁端保持原位，静态与运行时姿态一致。预览：`outputs/sts_platform_center/after.png`。

完整重建顺序：`build_sts_dimensions.py` → `build_sts_elevation.py` → `build_sts_track_gauge.py`。各构建器会静音自己及后续覆盖层，避免重复执行累积移动。控制面板会为未加载这些层的旧场景按顺序挂入会话层。

单独撤回本次轨距调整时，先关闭控制面板，再静音 `sts_track_gauge.usda`（若会话层另有引用也需移除）。撤回更早的高度或尺寸层时也要先撤回轨距层。测试：`tests/test_sts_track_gauge.py`；预览：`outputs/sts_track_gauge/after.png`。

### 立柱再加高一倍、上层平台向海侧移动

`sts_elevation.usda` 叠加在尺寸层之上，此次只改变立柱段高度和上部结构位置：

- 7 台岸桥的四根主立柱由约 20.52 米加高到 41.04 米，柱底不动，门架跨度保持 15.54 米；轮组、轮轴、底部连接和柱脚加强板保持原位、原尺寸。
- 立柱、斜撑和梯架沿柱底基准延长；前后主梁、机房、上部平台及塔顶整体抬升约 20.52 米，并整体向海侧移动 3 米，平台厚度不变。
- 吊具初始高度和尺寸保持不变，仅向海侧随小车平移；吊绳加长，起升上限、抬梁停机坐标及联锁阈值随抬升量增加。
- 修改海移量可调整 `build_sts_elevation.py` 中的 `SEAWARD_SHIFT_M`。重建后继续运行 `build_sts_track_gauge.py`，以保留最新轨距；均不会累积缩放。
- 关闭控制面板后静音 `sts_elevation.usda` 可单独撤回本次抬高/海移；若撤回底层尺寸调整，也必须同时静音此层。会话中另行挂入的层也需移除。
- 测试：`tests/test_sts_elevation.py`；预览：`outputs/sts_elevation/after.png`。

### 先前的两倍整体高度与加宽门架跨度（底层）

`sts_dimensions.usda` 是独立的尺寸覆盖层，保留已有模型、材质和吊具定制：

- 7 台岸桥在当前模型基础上整体高度 ×2；轮底对齐连续轨道顶面。
- 海侧轮组中心和前臂水平伸出长度不变，门架在上次加宽结果上再加宽 50%，轮组间距从约 10.36 米变为 15.54 米（原始 5.18 米的 3 倍）；尾梁、机房、塔顶与后拉索同步展开。
- 平台相对原始布局向陆侧加宽 20 米，总宽 40 米；四条引桥缩短并衔接新边界，陆侧标线和支撑同步调整；船边作业车道保持不变。
- 高度是整个岸桥的纵向缩放（含梁、轮组和吊具）；控制值仍是局部轴坐标，不直接等于世界米数。起升 1 单位对应世界 Z 位移 2.4 米。
- 在 pxr 环境运行 `omniverse/scripts/build_sts_dimensions.py` 可重建覆盖层。构建时静音旧覆盖层，因此重复执行不会累积放大。
- 已打开的场景可重新执行 `sts_control.py`，安全挂入尺寸层，无需丢弃未保存修改；正常重新打开主场景也会自动加载。
- 回退尺寸时先关闭岸桥控制面板，再同时静音 `sts_elevation.usda` 和 `sts_dimensions.usda`；若曾在会话层挂入，也需从会话层移除该引用。

尺寸回归测试：`tests/test_sts_dimensions.py`，覆盖全部岸桥比例、轮轨对齐、前臂位置、静态/动态拉索和引桥衔接。

- `blender/build_sts_control_asset.py`：从现有静态 USDC 拆分生成控制模型。
- `omniverse/scripts/build_sts_control_layer.py`：按当前岸桥位置生成控制场景层。
- `omniverse/scripts/sts_control.py`：运动计算、联锁和控制面板。
- `tests/test_sts_control.py`：真实 USD 层级、变换、绳端点、联锁和清理集成测试，需 pxr 环境。
- `outputs/sts_control/`：工作、移动、停机和抬梁验证姿态，以及预览图。

要回到静态岸桥，可在 Layers 面板静音 `sts_controls.usda`，并关闭控制面板。

### 底部横梁与八轮行走机构

- `sts_running_gear.usda` 为 7 台岸桥增加两侧连接横梁、四个加宽并外扩的立柱支承座。
- 每侧两组四轮，共 8 个轮子；每台 16 个。轮距 1.10 米，单个支承座长 4.55 米。
- 两排立柱沿轨道方向各向外移 2 米，柱身内侧净距由 7.04 米增至 11.04 米；轮组、爬梯和侧向支撑随动，底部连接梁和顶部承接梁跨越扩大的开口。
- 上层主平台和前后臂平台同向总加宽 4 米，边板、走道与护栏各外移 2 米；固定段与俯仰段保持连续，小车轨道、吊具、机房及拉索锚点保持原有控制尺寸。
- 旧轮组隐藏，新轮组随 `Gantry` 整体移动；此层提供外观几何，不新增轮轨物理约束。
- 在 USD Python 中运行 `build_sts_running_gear.py` 重建，运行 `verify_sts_running_gear.py` 检查数量、间距、立柱净空及大车运动继承。
- 如重建尺寸、高度或轨距，先静音此层，完成后重新运行行走机构构建脚本；静音此层可恢复原底座轮组。
