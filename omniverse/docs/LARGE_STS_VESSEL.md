# STS01–STS03 共用大型集装箱船

## 当前 6.6 结构快照

当前场景优先加载 `ship_structure_boxes.usda`，由用户提供的 `data/vessel_structure.sample.json` 生成。它覆盖并停用原始示意配载 `Model` 和旧 `BayPlan`，不再随机填满其他倍位。快照包含 01、03、05、07、09 五个倍位的 H（舱内）/D（甲板）共十组、507 个有效箱位，其中舱内 165、甲板 342。声明的层表最高到 96，但实际 locationList 最高为 92；不会根据层列笛卡尔积补出缺失位置。列序号用 rowList 的 rowSeq→rowNo 映射，层序号同理，校验其与 location 编码相符。

用户确认按奇数倍 20 尺、偶数倍跨相邻奇数倍的 40 尺规则绘制。原始 size=C/D/1 保留并分别以蓝、青、金色区分，不将这些编码自行映射成物理长度。三维单元表达结构箱位，不代表已装载实箱；实际装卸任务需配载清单，结构显示期间拒绝把这些示意单元当货物执行原演示任务。

三维箱体采用 `live_containers.usda` 中堆场箱的完整部件（瓦楞、箱门、门锁杆、角件、磨损），按标准米制尺寸归一化后以普通引用绘制。堆场六种涂装材质复制时重映射 shader 连接及材质绑定，避免跨作用域引用造成灰白显示。三维涂装按箱位稳定分配，二维箱图的 C/D/1 颜色仅用于显示原始编码。

当前实际实现按尺型和涂装分别选择堆场中的完整样箱，连同其烘焙在 `primvars:displayColor` 中的瓦楞、顶板、门框颜色一起复制，不再用单个红色样箱替换箱体材质生成其他配色。模型使用普通引用及按涂装区分的 `Geometry/Source_<paint>` 几何路径，避免运行中替换顶点数据后 RTX 复用旧缓存导致部分颜色不显示；实际船上引用关闭 instanceable。`ship:yardSourcePrim` 保留每种样箱的来源，自动检查全部涂装的细节颜色与堆场源一致。

甲板展示以每个倍位/列号的最低已返回层为可见堆垛底部，贴合前甲板或舱盖表面，上下模型按完整几何高度 2.591 m 接触堆放；原始 tier、rowSeq、tierSeq 和 location 保持不变。通过 `ship:displayBaseTier` 和 `ship:supportLocalZ` 记录这种可视化落地处理，避免源数据从 84 层开始时把整列箱悬在空中。舱内层保持原始结构高度映射。

源接口尺寸和 vcg/tcg 均为零，三维间距沿用项目米制标准，不解释零值为真实物理位置。船宽扩展至 40.6 m 以容纳返回的最大 15 列。原始 hatch 重复记录按 id 校验、去重并保留；hatchCover 为空，保留现有示意舱盖，不声称它来自接口。

在 Kit USD Python 环境运行 `python omniverse/scripts/build_ship_structure.py --source <JSON文件>` 可重建导入层。`python omniverse/scripts/render_ship_structure_plan.py` 可输出按倍展开的箱图。下面的原始 01–59/62 配载布局仅为被覆盖的演示模型。

`large_sts_vessel.usda` 将前三艘靠泊小船替换为一艘连续船体。其他靠泊船、远处船舶和出港动画保留。船体长 248 m，宽 40.6 m，沿世界 Y 轴布置，船首 Y=-4，船尾 Y=244；水面基准 Z=-4.9478 m。这些尺寸是根据项目泊位空间设计的示意值，并非 TOS 实测船型参数。

布局依据用户提供的两张船图：

- 20 尺倍位为 01、03、…、59；驾驶楼在 43/45 倍之间；船尾单列 40 尺倍位 62。
- 普通 40 尺箱跨相邻两个 20 尺倍位，使用其间偶数倍号，例如 01/03 → 02。
- 横向列号为 12、10、08、06、04、02、00、01、03、05、07、09、11。
- 舱内层号 02–16，甲板层号 82–90，步长均为 2。
- 集装箱保持标准长宽高，独立箱体用 USD 原生实例共享瓦楞、门锁和角件几何。

船首船尾使用插值后的连续横剖面网格，带外飘船首、弧形舭部、球鼻艏和收窄船尾；船首尾甲板随舷缘略微升高。细节包括贴合曲线的护栏、锚链和锚、锚孔、系泊绞车、双系柱、尾部导缆环及平台、导航桅杆、水下螺旋桨和舵。驾驶楼增补侧窗、翼台玻璃和外部爬梯。甲板基准为水面上 9.4 m，龙骨基准为水面下 12.8 m。

`BayPlan` 保存倍位、列号和上下舱层号；`Model` 中的箱体保存 `ship:sizeFt`、`ship:bay`、`ship:row`、`ship:tier`、`ship:location`。场景货物为固定演示配载，与真实 TOS 清单分开；船尾 62 倍的列数收窄，不设舱内层。

重建命令（需要 Kit 的 USD Python 环境）：

```text
python omniverse/scripts/build_large_sts_vessel.py
```

主场景在 subLayers 中加载本层。Agent 启动时也会将其挂入已打开的场景会话，保留其他会话修改；TwinState 不再重建被替换的小船。STS01 单箱、STS03 双20演示入口改为引用新船上的箱体。`large_vessel_layout.py` 提供统一路径及坐标换算。

## STS01–03 外伸臂延长（2026-11-02）

`sts_boom_extension.usda` 独立覆盖层将三台岸桥外伸臂纵向延长至原来的 2.5 倍，约 44 m，轨道海侧端达到世界 X=-286.77 m，覆盖当前大船外舷 X=-283.1 m。其他四台岸桥保持原样。

保留原有 Gantry/Boom/Trolley/Hoist 节点及铰点；长梁、轨道、走道、纵向栏杆只沿长度方向调整。端盖、螺栓、横向构件、灯具刚性平移，并补充栏杆立柱。拉索锚点随新臂长及起臂角度更新。小车上限从 17 调为 42.98（原局部控制坐标），原陆侧下限、吊具尺寸、门架、起臂联锁与急停逻辑保留。

生成脚本：`omniverse/scripts/build_sts_boom_extension.py`。运行中的场景通过 `sts_boom_layout.ensure_live_booms` 更新，保留控制器状态和任务对象。几何为数字孪生展示模型，不代表机械承载结构设计或真实设备 PLC 限位修改。

验证：新增臂架几何、覆盖范围、非目标岸桥不变、小车限位、起臂联锁、拉索跟随和急停检查通过；现有 STS 控制 9 项测试通过。原生渲染截图已检查。
