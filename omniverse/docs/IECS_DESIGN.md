# IECS 统一设备与集装箱调度系统设计

状态：设计方案，尚未实现调度服务。首期目标是本项目 Kit 场景中的
多车、多设备标准流程自动化演示；实机控制后续通过独立适配器接入。
名称：IECS（Integrated Equipment and Container Scheduling）。

## 1. 系统边界

IECS 接收运输/装卸订单，选择车辆、岸桥、RTG 和箱位，编排任务，
预约道路及交接区，根据设备回执更新车辆、箱子和任务状态。
Kit 负责执行模拟动作和显示结果。订单、资源预约和箱位记录由 IECS
统一管理，不能依靠 USD 中模型的可见性推断任务成功。

首期使用编号 01–20 的停车集卡；内部稳定 ID 为 ITT-001–ITT-020。
外来集卡使用 EXT-* 独立编号。设备与 USD prim 使用映射表绑定，
不能每次派车创建一辆替身而让停车场原车仍留在原位。

## 2. 模块和接口

| 模块 | 职责 |
| --- | --- |
| 调度工作台 | 全场地图、订单、设备状态、箱位、告警、演示启动与暂停 |
| 流程编排 | 将订单拆成有前后依赖的车辆移动、取箱、交接、放箱步骤 |
| 资源调度 | 车辆选择、岸桥/RTG 队列、停车位和交接位预约 |
| 交通管理 | 有向路网、车辆限速、路段/路口预约、停车等待和重规划 |
| 箱务管理 | 箱号、尺寸、当前位置、目标位、占用/预占和搬移记录 |
| 设备适配 | Kit 运动控制与状态回执；未来的 PLC/设备系统适配 |
| 事件与恢复 | 可重放事件、超时、失败重试、断连恢复和演示复位 |

工作台通过 HTTP 获取资源和创建订单，通过 WebSocket 订阅事件。
IECS 与 Kit 使用专用带确认的命令通道，状态通道只负责遥测。
现有 48700 TwinState 接口和 48710 桥接需要逐项核对能力，不应直接
假定其支持多车任务或任意脚本执行。

首期建议采用单个模块化 Python 服务、SQLite 事务存储及独立工作台，
降低在本机启动演示的复杂度。Kit 插件通过主线程更新回调应用动作。
可根据工作台选型接入 Qt、现有桌面客户端或 Web 界面。

## 3. 核心数据

- Vehicle：稳定编号、车型、尺寸、速度、空载/载箱、当前位置、任务、健康状态。
- Equipment：岸桥/RTG 编号、可服务区、动作状态、作业能力、预约队列。
- Container：唯一箱号、20/40 英尺、所在船位/车架/吊具/堆场位、版本号。
- Location：停车位、闸口、等待点、岸桥交接位、堆场区/贝/排/层、船舶箱位。
- Order：业务类型、源位、目标位、箱号、优先级、指定或自动选择设备。
- TaskStep：动作、设备、依赖、命令 ID、执行状态、超时和反馈。
- Reservation：车辆、设备、道路、交接位及目标箱位的预约与释放条件。

箱子任何时刻只有一个归属位置。取箱提交时验证源位及箱版本，放箱
完成回执后原子更新归属；运动中可明确记为吊具上。40 英尺箱预约
成对贝位，不可只锁单个标记；上层箱占用、承重/支持位和目标冲突
必须先检查。船舶与堆场库存均参与演示快照。

## 4. 调度和交通规则

堆场内所有集卡作业车道从大贝位向小贝位单向行驶。去目标小贝位时
也必须先到该区大贝位入口，不允许为了缩短距离从小贝位端逆行。
横路、引桥、外侧主路双向；岸桥下四车道为 2+2，停车位接入外侧主路。
闸口按当前设计暂定 4C 前方横路外侧延长段，需在工作台标明并现场核对。

路网由节点（入口、交叉口、停止点、交接点）和有向边组成。
不能仅按标线中心连接折线：车辆尺寸、轨迹扫掠、转弯半径、岸桥腿部
及灯杆净距检查通过后，该段才可开放给对应车型。绘制车道宽度与现有
紧凑模型尺寸采用一致的场景标定，不预先假定它们全部是真实工程尺寸。

首期以确定性调度为主：按优先级/等待时间选订单，按预计完成时间选车，
综合空驶距离、设备等待和道路拥堵。距离必须来自可通行路网。
预约失败在安全等待点停下，不在路口内等待。车辆进入路口前预约完整
冲突区和出口容量，避免堵塞；路段释放以车尾离开为准。
设备故障使相关任务暂停并释放可安全释放的预约；已在吊具上的箱子
保持归属，不通过直接换车或重发命令假装完成。死锁检测后按任务优先级
和等待时长重规划，失败则暂停并提示。

## 5. 命令和流程状态

订单状态：待校验 → 待资源 → 已分配 → 执行中 → 完成。
旁路状态：暂停、失败、取消；取消需要进入安全状态后才能结束。
步骤状态：等待依赖 → 已预约 → 已下发 → 已接受 → 执行中 → 成功/失败。

命令至少包含 commandId、orderId、stepId、设备 ID、动作、参数、序号和
预期资源版本。Kit 回传 Accepted/Started/Progress/Completed/Failed。
重复命令返回之前结果；到点不等于交接完成，必须等装卸完成回执。
首期速度倍率使用统一仿真时钟，暂停同时冻结运动和预约时间推进。
流程结束或复位检查预约是否残留，记录原因。

## 6. 标准自动化演示

| 流程 | 自动执行步骤 | 完成条件 |
| --- | --- | --- |
| 卸船入场 | 停车场空车出发 → 岸桥交接 → 卸船装车 → 引桥 → 大贝位端进入 → 目标贝位 → RTG 卸车入堆 → 空车驶出回停车场 | 箱子在目标位，车辆归位，源船位清空 |
| 堆场装船 | 空车出发 → 大贝位入口 → 源贝位 → RTG 装车 → 小贝位端驶出 → 岸桥 → 吊箱上船 → 空车回停车场 | 箱子在船位，源堆场位清空 |
| 外来集卡进场落箱 | 载箱外车进闸 → 校验箱号/订单 → 指定堆场 → RTG 落箱 → 空车出闸 | 箱子入堆，外车离场，闸口记录完整 |
| 外来集卡提箱出场 | 空外车进闸 → 指定堆场 → RTG 装箱 → 载箱出闸 | 提箱完成，箱子归属离场交接记录 |
| 场内转栈 | 停车场派空车 → 源区 RTG 装车 → 目标区 RTG 落箱 → 归位 | 源位释放、目标位占用，箱号不变 |
| 多车混合作业 | 并发提交以上订单 → 多车排队与路口预约 → 设备队列交接 | 无重复派车/重复箱，全部订单有最终结果 |

第一条优先实现已有 STS 卸船演示的调度化改造，再做装船和外来集卡
两条流程，最后开放混合作业。已有固定 2C004 目标和旧路线不能直接
视为符合单向车道的新方案；需参数化和路网规划替换。

每条演示提供开始、暂停、继续、单步、速度倍率、重置，以及任务跟随。
重置恢复专属演示会话中的车辆、库存、设备位姿和预约快照。
正常完成保留库存变化；不可由面板关闭隐式撤销已完成订单。
可用固定随机种子和显式资源配置重现演示结果。

## 7. 工作台布局

中央：二维交通与箱位地图，可关联 Kit 摄像机跟随。
左侧：标准流程按钮、订单创建、任务队列和任务步骤。
右侧：车辆 01–20、岸桥、RTG 实时状态及交接队列。
底部：时间线、告警、箱位变更、路口预约和调度指标。
点击车辆显示任务、所载箱、规划路线及等待原因；点击箱子显示从船位
到堆场/闸口的完整记录。指标包括完成单量、等待时间、空驶距离及设备利用率。

## 8. 实施顺序与验收

1. 建立资源清单、稳定 ID、路网与库存快照；核对场景物理净距。
2. 实现 IECS 服务、状态机、工作台与 Kit 适配器，跑通单车卸船入场闭环。
3. 接入装船、外来集卡进/出场及转栈；演示可暂停/重置。
4. 从 2 辆车逐步扩展到 20 辆，加入路口预约、拥堵、故障与恢复。

验收要求：所有堆场移动符合大贝位→小贝位；车箱身份一致；箱子不复制；
设备/车辆不重复分配；每次交接有回执；路口不相撞；重置可复现初始状态。
连接中断、重复回执、设备忙、目标位被占、道路不可通行都应得到可解释结果。
运动学演示验证和实机安全认证是独立工作，首期演示不接实机写控制。
