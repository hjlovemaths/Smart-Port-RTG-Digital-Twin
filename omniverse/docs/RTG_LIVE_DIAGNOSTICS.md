# TwinState 库存同步、抓箱对位和性能修复

2026-10-28 修复版本：`2026-10-28-authoritative-task-map-lock-foot-alignment-v3`。
更新后重启 Kit 应用，再启用 TwinState receiver。外部 PLC 消息服务可以保持运行。

## 任务箱区图优先

- 收到有效 `bayMap`（六位，R1 到 R6，每位 0..6）时，以任务数据更新对应贝位的本地库存。
- 同一个任务补发或修正 `bayMap`、`targetBayMap`、`baySlotHeights`、箱型／箱高时也会同步，
  不再只根据任务编号判断是否需要刷新。帧时间、任务年龄的变化不会触发重建。
- 当前任务使用的临时箱区立即按新库存重绘。隐藏的持久库存模型在重新显示前刷新，
  避免切换任务后旧箱子重新出现。`000000` 会清除旧箱子。
- 地图修正保留当前集卡和作业阶段，并更新状态机采用的堆高、放箱接触高度。
- 已结算任务的重复完成消息不会把其作业前箱区图写回库存。
- 重建时还会屏蔽 `live_containers.usda` 等底层 USD 文件中的旧箱子。
  单独调用 `RemovePrim` 只删除当前会话层，不能清除较弱图层里的定义；
  旧层多余的箱体与装饰网格现在会在会话层停用，新生成的箱子会恢复正确的可见性。
  场景源文件保持原样，旧库存不再叠加显示。
- 不完整、无效的实时箱区图保持待同步状态；跨贝倒箱在缺少全场同步时还需要 `targetBayMap`。
  任务提供的六位箱区图只说明数量，逐箱高度仍以提供的 `baySlotHeights` 为准；
  没有逐箱高度时沿用已有有效数据或默认层高。

发生层数变化时，日志会显示：

```text
[RTG Twin Driver] task bay-map synchronized task=... bay=4C/028 cached=011500 authoritative=011300
```

## 吊具横向偏差

最近整机轮胎轨道对齐改变了 RTG 的横向基准，但小车仍按旧视觉换算定位，
实测四个锁脚中心相对箱排中心约偏移 0.23 米（USD 场景坐标）。

控制器现在绑定模型时测量四个可见红色锁脚，根据当前整机位置校准小车的视觉平移。
PLC 输入米数、工程限位和驱动目标表保持原有含义。校准只计算一次，重复绑定不会叠加偏移。
缺少这套锁脚几何的简化模型继续使用原有映射。

使用当前完整模型验证了 20／40 英尺箱、六排箱位及集卡停位的横向对齐。
40 英尺大车贝位中心仍与箱体中心一致；20 英尺保留原有停靠标定。
第四层标准箱对应的吊具接触面、悬吊箱顶面和堆叠高度也已验证。

## 货车载箱纵向偏后

导入货车原先套用程序生成货车的驾驶室定位，实际挂车侧梁与箱体中心错位。
40 英尺箱后端比承载区后缘多伸出约 0.52 米。

现在使用导入模型侧梁的实际纵向范围定位车身：40 英尺箱居中，20 英尺箱靠前并保留
0.25 米前端余量。箱体本身的抓放中心、货车停车坐标和起升高度保持原有标定。
验证包含 LOAD／UNLOAD 两种任务、驾驶室间隙以及离场时车身与箱体相对位置。

## 接收循环的 CPU 开销

RunInfo 面板原先每条消息会两次遍历完整 RTG 计算世界包围盒。
现在首次计算其顶部锚点，之后通过大车变换跟随，停止或切换场景时清除缓存。

在独立 USD 进程中回放同一组采样，20 次稳定消息的 CPU 时间由约 1.72 秒降至约 0.11 秒。
这是接收逻辑的 CPU 测量，不代表实际 GPU 渲染 FPS。
