# 智慧港口整体系统发明专利技术交底书（讨论初稿）

版本：v0.1  
编制日期：2026年10月30日  
拟定名称：一种基于高保真数字场景和智能体交互的港口仿真联调方法及系统

## 一、交底范围和事实状态

本稿围绕用户提出的整体系统展开：以完整、逼真的港口仿真界面为交互载体，通过IECS连接TOS、调度及控制算法、PLC与数字设备，兼顾港口作业仿真、内部联调、运行监控，并接入AI Agent进行查询和操作编排。

全文采用以下标识：

- 【已有基础】：已在本地代码或项目文档中发现对应实现，不等于已完成生产验证。
- 【拟申请设计】：为把整体构想写成可实施技术方案而提出的设计，尚不能表述为项目已实现。
- 【待核实】：需要发明人或对接资料补充确认的事实。
- 【待验证效果】：需要对比试验支持的预期效果，本文没有填写虚构数据。

本文是供发明人补充、检索和代理人讨论的工程交底初稿。候选权利要求尚未完成新颖性、创造性和支持性审查。

## 二、拟保护的整体构思

以设备、集装箱、作业任务与场景对象的关联关系为基础，把高保真三维港口作为可执行、可查询、可追踪的作业环境；自然语言请求由Agent转换为带设备和任务标识的结构化操作，经IECS及运行上下文校验后，在指定的真实或虚拟执行链路中执行；执行反馈驱动任务状态和同一三维场景更新，形成可供操作员观察、追问和进一步操作的闭环。

候选技术主线为：

**任务与场景对象绑定 → Agent结构化操作 → 运行上下文与控制权校验 → 真实/虚拟执行链路路由 → 作业交接结果校验 → 场景和运维状态同步反馈。**

“完整界面、画面逼真、接入AI Agent”是产品特点。拟主张的技术贡献需要落实到上述各环节如何协同，以及这种协同解决了什么具体问题。单独增加模型细节或聊天入口，不直接证明创造性。

### 2.1 高保真的含义

本方案将高保真拆为可分别验证的三个层面：

| 层面 | 内容 | 当前判断 |
| --- | --- | --- |
| 视觉真实感 | 港区布局、设备模型、箱体细节、材质、照明、昼夜、雨雾与观察视角 | 【已有基础】有相关场景与脚本；未建立统一视觉评价结果 |
| 作业与状态一致性 | 可见设备及箱体与任务、位置、载箱归属、设备状态相对应 | 【已有基础】部分流程、实体检查、库存同步已实现；全港一致性需补强 |
| 物理与传感器可信度 | 接触、锁定、支撑、动力学及传感器输出与工程过程相符 | 【已有基础】有局部原型；全港工程精度和实物对比【待验证】 |

不能以画面真实感替代物理模型精度。工程坐标与压缩或非等比缩放的场景坐标必须显式转换，接触容差应注明所属坐标系。

## 三、技术领域、背景和待解决问题

技术领域：港口自动化设备仿真、数字孪生、工业控制系统联调、三维交互和智能体工具调用。

相关系统已存在TOS/ECS集成、设备调度、三维显示、数字孪生及控制仿真等公开方案，见第十三节。本稿不将这些功能本身认定为首次提出。

本方案拟针对以下问题：

1. 三维设备、后台任务和控制接口采用不同标识，操作员观察到的对象难以对应具体任务或控制命令。
2. 自然语言中“这台RTG”“当前卸船任务”等指代可能存在歧义，操作目标或运行环境不明确。
3. 联调时部分组件是真实软件或控制器，部分是仿真组件，指令与反馈的接口语义、时序和归属容易不一致。
4. “指令已接受”“模型已到位”和“装卸交接已完成”容易被混同，导致任务过早完成或箱体归属错误。
5. 在生产映射与仿真测试共存时，迟到回执、旧会话命令和模拟库存可能进入错误状态空间。
6. 任务异常需要在TOS订单、IECS步骤、算法输出、PLC反馈与三维场景之间反复查找，缺乏统一关联依据。

以上问题需结合实际对接故障记录确认，不能笼统断言所有现有系统均存在这些缺陷。

## 四、系统组成

以下为【拟申请设计】；对应现有实现见第十二节。

| 模块 | 主要职责 | 与其他模块的具体关联 |
| --- | --- | --- |
| 港口数字场景 | 组织岸桥、RTG、船舶、集卡、堆场、箱体、道路及环境；显示运行状态 | 每个可操作对象关联设备或集装箱稳定ID及当前任务 |
| TOS适配模块 | 将外部作业订单转换为统一订单，回传完成或异常结果 | 保存外部订单号与内部订单ID映射 |
| IECS编排模块 | 分解任务、安排设备与交接依赖、管理资源状态 | 生成步骤ID及执行条件，接收设备和交接回执 |
| 算法接入模块 | 接入设备选择、交通规划、对位或其他控制算法 | 声明输入状态版本、输出对象、参数单位和适用运行环境 |
| 执行适配模块 | 对接真实控制器、虚拟控制器或虚拟设备 | 统一命令及反馈语义，维护各设备当前执行绑定 |
| 运行上下文管理模块 | 区分仿真、在线映射、混合联调及可选现场控制 | 校验环境、会话代次、绑定版本与控制权 |
| 状态及事件模块 | 关联订单、步骤、命令、设备、箱体和场景事件 | 校验事件归属，更新相应环境中的任务和实体状态 |
| AI Agent模块 | 将自然语言转换为查询或结构化操作，解释执行结果 | 使用注册工具和对象目录；操作请求进入IECS或对应执行校验链 |
| 运维交互模块 | 在同一场景上显示设备、任务、告警、历史与操作结果 | 与Agent读取相同的已校验状态，显示来源及更新时间 |

## 五、关键数据与接口语义

### 5.1 对象关联

【拟申请设计】建立下列关联记录：

SceneBinding = 场景对象标识、实体ID、实体类型、订单ID、步骤ID、运行上下文、坐标映射版本。

设备和箱体保持稳定实体ID；三维模型因重建而改变路径时，更新绑定版本。不能仅凭场景节点名称或模型颜色认定设备身份。

界面选择对象可提供实体ID给Agent；未选择对象时，Agent通过目录和当前任务筛选候选。存在多个候选时先明确对象，不由模型任意猜测。界面选择到Agent的直接上下文传递【待实现核实】。

### 5.2 运行上下文

【拟申请设计】RunContext至少包括：

| 字段 | 含义 |
| --- | --- |
| environmentId | 生产、测试或独立实验环境标识 |
| runId | 一次运行或联调会话标识 |
| epoch | 会话或执行绑定切换后的代次，用于阻断旧指令和旧回执 |
| mode | 当前运行方式 |
| bindingVersion | 设备到实际执行端点的映射版本 |
| clockPolicy | 仿真时间、墙钟时间及控制通信计时的使用规则 |

运行方式与生产设备自动/手动/维修模式分别记录。界面选定仿真模式不改变真实设备工作模式。

### 5.3 命令与反馈

命令候选字段：RunContext、commandId、orderId、stepId、entityId、action、参数及单位、expectedStateVersion、sequence、timeoutPolicy。

反馈候选字段：RunContext、commandId或经适配建立的关联键、entityId、status、measuredState、stateVersion、来源、源时间、接收时间、拒绝或失败原因。

状态至少区分Accepted、Started、Progress、Completed、Failed。Accepted只表示接收或通过入口校验，不能单独作为交接完成条件。

外部PLC协议若不能携带上下文字段，适配器需保存原生命令与内部命令的映射。无法可靠关联时，不得虚构精确匹配关系；应标为未关联反馈，并保持相应步骤待核实或超时。

## 六、核心方法流程

以下S1—S8为【拟申请设计】。

### S1 建立场景与实体绑定

载入港区数字场景及设备、箱体目录，建立实体ID与场景对象、控制接口及坐标转换的关系。对设备位置、吊具状态、箱体归属和箱位占用分别维护状态来源。

场景显示依赖已校验状态。界面隐藏模型不能等同于箱位释放，模型到位不能等同于设备已完成交接。

### S2 建立运行上下文并绑定执行端点

选择运行方式，明确TOS、IECS、算法、控制器、设备模型各自为真实组件还是仿真组件，生成组件绑定表。

绑定声明包括命令能力、参数单位、反馈字段、时序要求及是否涉及真实设备写入。缺少能力的执行端点拒绝相应动作，不能静默降级为“执行成功”。

### S3 接收作业目标

接收TOS订单、测试订单或Agent发起的操作请求，解析作业类型、箱号、源位、目标位及指定设备。

Agent使用注册工具生成结构化请求。校验操作对象、运行上下文、参数范围、状态新鲜度与控制权；对象不明确或前置条件不满足时，返回缺失信息或拒绝原因。

### S4 分解步骤并建立交接依赖

IECS将订单分解为车辆到位、岸桥装车、车辆运输、RTG卸车入堆等步骤。每一步保存动作设备、依赖步骤、占用资源和完成证据。

箱体归属在船位、吊具、车辆与堆场位之间按有效交接结果更新。对于真实业务库存，采用对应业务系统允许的提交接口；仿真库存仅在当前运行环境更新。

### S5 分发算法请求与控制指令

算法读取指定版本的设备、路网和箱位状态，输出计划或控制目标。IECS校验输出对象及状态版本后，将带上下文的控制请求发送至当前绑定端点。

设备有多个驱动来源时，执行前检查互斥控制权。用于联调的真实PLC与实体执行器的输出连接必须通过现场接线或控制器配置明确隔离；不能仅依赖界面模式标签认定隔离有效。

### S6 生成或接收设备结果

真实链路接收控制器及设备反馈；虚拟链路根据运动、接触、约束和交接状态生成反馈。

抓放箱实施例可采用四锁脚着箱与对位、箱型匹配、固定约束建立、运动扫掠检测及四底角支撑后释放约束。起重机运动学与载荷独立物理步进是可选具体实现，不作为所有设备模型必须采用的唯一方式。

### S7 校验反馈并推进任务

接收反馈后依次检查：

1. 环境、runId及epoch是否匹配。
2. 绑定版本、设备身份与来源角色是否符合当前步骤。
3. 命令是否存在，回执是否重复或已被更高序号覆盖。
4. 当前步骤是否满足状态转换和交接完成条件。
5. 资源、箱体归属或目标位版本是否仍有效。

校验通过后，更新对应环境的任务及实体状态，并记录事件；不通过的反馈保留原因但不推动当前任务完成。涉及库存提交时将任务完成、箱位变更与提交结果关联，失败不得仅显示为成功。

### S8 同步场景并反馈操作结果

将有效状态映射到三维设备位置、吊具状态、箱体位置及告警标记，同时更新运维面板和Agent可读状态。

Agent依据执行回执报告“已启动”“已完成”或“失败”，并引用订单、步骤和设备标识。无充分故障证据时只描述已观察到的阻塞条件，不将语言模型推测当作诊断结论。

## 七、运行方式与环境切换

### 7.1 运行方式

| 方式 | 输入及执行 | 状态权威来源与输出边界 |
| --- | --- | --- |
| SIMULATION：离线仿真 | 测试/历史订单，经IECS和仿真算法控制虚拟设备 | 仿真状态保存在独立runId；不写生产业务库存 |
| ONLINE_SHADOW：在线映射 | 接收现场订单、设备及PLC状态，驱动数字场景 | 现场反馈与业务系统分别对其状态负责；不向实体设备发运动指令 |
| INTEGRATION_TEST：混合联调 | 被测TOS、IECS、算法或PLC与仿真替代组件组合 | 执行与回执均限制在当前测试上下文；被测实物控制器需确认执行器隔离 |
| ONLINE_CONTROL：可选现场执行 | 经授权的IECS与现场适配器向真实设备下发操作 | 【拟扩展、待核实】不等同于现有项目已实现，不由仿真成功直接触发生产执行 |

运维界面与Agent是跨方式的访问入口，不单独决定执行通道。

### 7.2 切换过程

【拟申请设计】切换采用有条件的绑定替换：

冻结受影响对象的新命令 → 确认在途命令与载荷归属 → 满足目标环境的切换条件 → 撤销旧绑定和控制权 → 增加epoch → 建立新绑定并校验初始状态 → 恢复可用操作。

载荷悬吊、任务交接中或状态来源未确认时，允许拒绝切换并保留旧上下文。不得把回滚场景快照当作回滚真实设备动作。

暂停仿真时可冻结仿真步骤及仿真超时；真实网络连接看门狗仍按单调墙钟计时。混合联调包含真实PLC时，默认按实时节奏运行，能否加速须由各被测组件能力决定。

## 八、贯穿实施例：卸船入场

以下示例ID仅用于说明协议，非真实订单或实测记录。

订单ORDER-001：将集装箱BOX-001从船位SHIP-SLOT-01，经岸桥STS-01、集卡ITT-001和RTG-01送至指定堆场位。

| 步骤 | 执行对象及动作 | 必要完成依据 |
| --- | --- | --- |
| P1 | 选择车辆、岸桥、RTG及目标位 | 设备可用，目标位及交接资源满足条件 |
| P2 | 集卡到岸桥交接位 | 位置及到位状态有效，车辆处于可交接状态 |
| P3 | 岸桥取船箱并放至集卡 | 对应箱号的吊具/车辆交接完成，箱体归属更新 |
| P4 | 集卡沿指定路网运输 | P3完成后放行；受交通规则和占用约束 |
| P5 | 集卡进入RTG交接位 | 指定车辆、箱号和位置匹配 |
| P6 | RTG取车箱并落入目标位 | 抓取、搬运、支撑及释放完成，源位/目标位状态匹配 |
| P7 | 汇总订单结果 | P1—P6证据完整，向对应TOS或测试订单源返回结果 |

### 8.1 离线仿真

测试订单源生成ORDER-001，使用虚拟岸桥、集卡、RTG和模拟反馈执行P1—P7。高保真场景展示同一BOX-001的全过程；运维面板展示任务阶段和等待原因。Agent可查询或通过已注册接口暂停当前测试流程。

【已有基础】IECS已有五类流程、场景设备动作及状态查询。统一TOS订单模型、上述完整上下文与回执校验属于【拟申请设计】。

### 8.2 在线映射

接收现场实际订单及设备数据，按关联关系把P1—P7的真实状态映射到场景。缺少某一设备反馈时标明缺失或过期，不以预设动画补出“真实完成”。

Agent查询“这单为什么停住”时，返回有数据支持的设备、任务步骤及最近回执；仅有停机状态不能自动推出设备故障根因。

【已有基础】存在RTG PLC/任务消息转TwinState以及数字设备状态驱动。覆盖全港的TOS字段映射、箱号绑定和跨设备关联【待核实/补充】。

### 8.3 混合联调

把被测算法和PLC控制程序接入测试上下文，虚拟RTG接收其控制输出，依据几何接触与载荷状态生成测试反馈。

可分别替换岸桥、集卡或RTG适配器，逐步构成全链路测试。Agent查询联调步骤并触发注册的测试工况；测试工况不能被路由到生产执行端点。

【已有基础】ZMQ接口可控制数字RTG并反馈状态；完整硬件在环传感器I/O映射、TOS闭环及多设备混合绑定【待核实/设计】。

### 8.4 交互场景示例

操作员在场景中选择RTG-01，输入“查看这台设备正在处理的箱子，聚焦交接位置，并解释当前等待条件”。

【拟申请设计】交互模块传递选中实体ID和上下文；Agent查询设备、订单及步骤状态，调用相机接口定位同一对象，并返回有来源的等待条件。

进一步请求“在测试环境暂停这单”时，结构化请求必须指定当前runId和orderId；IECS执行后，Agent依据实际结果报告状态。

当前已有相关查询、相机及IECS控制工具，但“选中对象直接传递给Agent”和该完整交互链尚未确认实现。

## 九、候选权利要求框架

本节用于检索和讨论，不是可直接提交的最终权利要求。整体方案的创造性仍需以具体区别特征及其协同效果论证。

### 9.1 方法独立权利要求候选

一种基于数字场景和智能体交互的港口仿真联调方法，其特征在于，包括：

1. 建立港口数字场景，并建立场景对象、设备实体、作业任务与执行接口之间的关联记录；
2. 建立包含运行环境、运行会话及执行绑定版本的运行上下文，根据该上下文将任务步骤中的设备绑定至真实执行组件或仿真执行组件；
3. 接收自然语言操作请求，利用所述关联记录确定操作对象和任务，将其转换为携带运行上下文及实体标识的结构化请求，并校验设备状态和控制权；
4. 依据任务步骤及其交接依赖，将控制请求经绑定的执行接口发送至对应组件，并接收关联的设备执行反馈或仿真执行反馈；
5. 校验反馈的运行上下文、执行绑定及任务步骤状态，在满足对应交接完成条件后更新任务和实体状态；
6. 依据更新后的状态同步港口数字场景和运行监控视图，并向智能体返回可关联至所述操作请求的执行结果。

最终独立权利要求是否必须限定Agent、是否以跨模式反馈校验作为核心，需结合检索结果确定。标题中的“高保真”应由具体场景绑定、坐标转换或交互处理支撑，不能仅靠主观画质评价限定范围。

### 9.2 从属技术特征候选

- 对象歧义时依据选中实体和任务关系筛选候选，不能唯一确定时先补充对象信息。
- 通过epoch递增及绑定版本校验隔离旧运行上下文的指令和回执。
- 对不支持内部上下文字段的原生PLC协议建立可核实的命令映射。
- 接触、闭锁、载荷支撑及交接完成信号分别参与任务转换条件。
- 将工程坐标与场景坐标转换版本关联到实体绑定，更新模型后重新校验几何关系。
- 切换执行环境前冻结新命令并确认在途命令及载荷归属。
- 仿真步骤计时与真实通信看门狗分别使用仿真时钟及单调墙钟。
- 基于同一有效事件同时更新三维场景、运维界面和Agent状态。
- 以订单、步骤、命令及实体标识关联事件，生成可追踪的异常信息。

### 9.3 系统权利要求候选

设置场景与实体关联模块、运行上下文与执行适配模块、任务编排模块、智能体交互模块、反馈校验模块及场景同步模块，使其执行上述方法。模块划分需与实际数据流一致，不以仅罗列模块替代技术关系。

## 十、候选摘要

本发明公开一种基于高保真数字场景和智能体交互的港口仿真联调方法及系统。建立港口场景对象与设备、作业任务及执行接口的关联关系，根据运行上下文将设备绑定至真实或仿真执行组件。将自然语言请求转换为携带实体标识及运行上下文的结构化操作，经状态与控制权校验后执行；依据反馈归属及交接完成条件更新任务和实体状态，同步三维场景、运维界面及智能体操作结果。该方案用于港口作业仿真、在线映射和混合联调中的对象关联与反馈一致性处理。
